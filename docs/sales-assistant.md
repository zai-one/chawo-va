# Chawo Voice Assistant — сценарий sales-ассистента

Поведение и формы данных. Один поток должен работать в локальной пробе Windows-клиента и позже в SaaS на другом стеке и другом бэкенде. Здесь нет поставщика CRM, нет схемы авторизации и нет адресов API. Описано, **как** появляется карточка на конкретном компьютере, **что** сервис подгружает и **какие** сущности ходят между границами.

Клиент на компьютере менеджера только рисует карточку и предлагает строки словаря. Он не решает, чей это звонок, и в SaaS не ходит в телефонию сам.

---

## 1. Привязка компьютера — один раз, не в момент всплытия

Добавочный номер **не вводит человек** в момент звонка. Его (или другой идентификатор трубки) определяет логика в системе. На компьютере заранее есть привязка.

Два допустимых способа завести привязку (достаточно одного):

1. **Вошёл менеджер.** На этом ПК открыт сеанс Chawo Voice Assistant под учётной записью менеджера организации (tenant). Сервис знает: этот компьютер = этот менеджер.
2. **Идентификатор softphone / трубки на машине.** На ПК установлен или зарегистрирован softphone, либо в настройках один раз указан id трубки / добавочный / device id, который телефония отдаёт в событиях. Сервис знает: этот компьютер = эта трубка = этот менеджер.

Результат привязки — строка карты:

- `pcId` — этот компьютер
- `managerId` / `managerName` — один менеджер
- `extension` и/или `handsetId` / `softphoneId` — то, с чем потом совпадёт событие звонка
- `trunk` — необязательно; если добавочные повторяются на разных транках

Позже приходит звонок. Сервис сопоставляет событие с картой. **Никто не печатает добавочный в окне всплытия.** Если совпадения с этим ПК нет — карточки нет. Если совпало с двумя разными ПК — это ошибка карты: карточки нет нигде, пока карту не поправят.

Локальная Windows-проба эту карту не хранит. Панель «Звонок (стенд)» — только подстановка тех же полей руками, с явной пометкой, что это стенд, не продукт.

## 2. Как замечается звонок на этом компьютере

Три источника — **альтернативы**, не обязательный набор. Достаточно одного. **Первое удачное совпадение с привязкой этого ПК побеждает.** Остальные для того же `callId` не открывают вторую карточку.

### A. Webhook телефонии (облако / АТС)

Внешняя телефония шлёт событие в сервис организации:

- `callId` — устойчивый id звонка
- `direction` — `inbound` или `outbound`
- `callerNumber` — номер другой стороны
- `extension` или id набранной / принявшей трубки, либо транк + добавочный

Сервис ищет привязку по трубке. Нашёл ровно один `pcId` — карточка уходит на этот компьютер. Ноль или больше одной строки — карточки нет.

### B. Локальное событие softphone на этом ПК

Softphone на машине сообщает приложению (или тонкому агенту): «я на линии», с номером и своим device id. Агент сопоставляет device id с привязкой **этого** ПК. Совпало — тот же поток, что у webhook. Softphone другого компьютера это событие не принимает.

### C. Горячая клавиша, когда менеджер уже в разговоре

Менеджер уже говорит (трубка вне интеграции, мобильный, чужой софт). Нажимает согласованную клавишу. Клиент на ПК говорит сервису: «открой карточку для **моей** привязки». Номер, если есть, берётся из того, что менеджер вставил / что отдал локальный softphone / что осталось от прошлого события; иначе карточка без номера. Это не ввод добавочного: добавочный уже в привязке ПК.

**Правило:** первое совпадение с этим `pcId` открывает карточку. Если ни webhook, ни softphone, ни клавиша не привязаны к этому ПК — карточки нет. Чужой звонок на чужую трубку сюда не приходит.

Событие «звонок закончился» (тот же `callId`) прячет карточку. Пока звонок открыт, живой черновик речи на том же ПК обновляет только каталожную часть и, если кода нет, фрагмент материалов. Смена менеджера или компьютера из черновика не делается.

## 3. Что сервис подгружает после совпадения

Порядок после удачной привязки к этому ПК:

1. **Клиент CRM по телефону.** Адаптер CRM — граница. По `callerNumber` отдаёт снимок или пусто. Пусто — нормально, пока CRM нет или клиент не найден: карточка всё равно открывается, без имени и без скрипта стадии. Адаптер не выбирает артикул и не рисует UI.
2. **Стадия сделки и скрипт этой стадии.** Из снимка CRM (`dealStage`, `stageScript`). Нет снимка — на карточке пометка, что скрипта нет.
3. **Каталог.** Точное попадание по коду в речи, иначе ближайший аналог (похожий код, история названных товаров при наличии CRM, иначе ближайшее название по буквам).
4. **Один фрагмент RAG** из индекса материалов организации — только вместе с аналогом (`similar`), не с точным кодом. Запрос — живой текст разговора.

На карточке сверху вниз:

1. Кто: менеджер, трубка (из привязки), номер. Нет номера — «номер скрыт». Нет CRM — «клиент по номеру не найден». Есть снимок — имя, компания, сделка, последний заказ (что непусто).
2. Скрипт стадии (или пометка, что данных нет).
3. Строка каталога; у аналога подпись «похоже».
4. Фрагмент материалов под аналогом.

## 4. Инструкции tenant для живой подсказки

У организации (и при необходимости у менеджера) есть текст **инструкции к подсказке на карточке** — не к расшифровке диктовки.

То же правило, что у мозга диктовки:

- **Пусто** — только убрать паразитов и шум в формулировке подсказки; **смысл не сокращать**, слова от себя не добавлять.
- **Написали своё** — выполняется только этот текст; дефолт «только паразиты» не применяется.

Инструкция влияет на **живую подсказку** (как подать скрипт / аналог / фрагмент менеджеру), **не** на транскрипт речи и не на словарь. Словарь по-прежнему меняется только руками (подсказки из материалов сами не пишутся).

## 5. Что у SaaS и что у локальной Windows-пробы

| Владеет SaaS (будущий сервис) | Остаётся / имитируется локально сейчас |
| --- | --- |
| Привязки ПК ↔ менеджер ↔ трубка | Нет; стенд подставляет поля руками |
| События звонка (webhook, маршрутизация) | Нет сети; кнопка стенда |
| Каталог организации | Список «код / название / строка» на этом ПК |
| Индекс материалов (RAG) | Папка `.txt` / `.md` на этом ПК |
| Скрипты стадий, инструкции tenant | Нет; CRM-адаптер всегда пустой |
| Доставка карточки на нужный `pcId` | Карточка только в этом процессе |

Локальная проба:

- сети нет;
- режим «Диктовка» карточку звонка не открывает;
- панель **«Звонок (стенд)»** явно подписана как замена события: человек заполняет добавочный, номер, имя менеджера и жмёт «Показать карточку»;
- эти три поля = одна строка карты пробы, `pcId` = `local`;
- адаптер CRM всегда пустой;
- каталог, папка материалов и «Подсказать из материалов» — как были.

## Границы

| Граница | Что отдаёт | Чего не делает |
| --- | --- | --- |
| Привязка ПК | Менеджер и `pcId` по трубке / сеансу | Не ищет клиента |
| Телефония / softphone / клавиша | Событие или «открой для моей привязки» | Не знает каталог, скрипт и материалы |
| Адаптер CRM | Снимок клиента по номеру или пусто | Не рисует карточку и не ищет артикул |
| Каталог | Строка по коду или ближайший аналог | Не заменяет CRM |
| Индекс материалов | Один фрагмент на карточку и подсказки словаря | Не пишет в словарь сам и не подменяет строку каталога |
| Инструкция tenant | Правило формулировки живой подсказки | Не правит транскрипт диктовки |

## Формы данных

Имена полей не привязаны к Windows и к WPF. Пустая строка = «нет значения».

### Привязка компьютера

- `pcId` — один компьютер
- `managerName` (или id менеджера в SaaS) — один менеджер
- `extension` — добавочный, если телефония шлёт добавочный
- `handsetId` / `softphoneId` — если совпадение идёт по id устройства, а не по добавочному
- `trunk` — пустое совпадает с любым транком; непустое — только с тем же

Разбор: совпал идентификатор трубки (и транк, если задан) **или** сеанс менеджера на этом ПК при событии типа «клавиша». Ровно одна строка — привязка есть. Ноль или больше одной — карточки нет.

### Событие звонка

- `callId` — устойчивый id; повтор обновляет ту же карточку
- `trunk` — группа линий; на одной АТС может быть пустым
- `extension` / `handsetId` — что сопоставляется с привязкой (для клавиши может быть пустым: берётся привязка сеанса)
- `callerNumber` — номер другой стороны; нормализация до цифр и «+» допустима, код страны не выдумывать
- `direction` — `inbound` или `outbound`
- `source` — `telephony` | `softphone` | `hotkey` (для аудита; на карточку не влияет)

### Снимок клиента (адаптер CRM)

Может отсутствовать целиком.

- `phone`, `name`, `company`, `openDeal`, `dealStage`, `stageScript`, `lastOrder`
- `spokenProducts` — что клиент уже называл или заказывал (строки, не чужие id)

Адаптер не выбирает артикул. История помогает выбрать аналог, когда кода в речи не было. Локальная сборка всегда возвращает отсутствие снимка.

### Строка каталога

- `code`, `name`, `line`, `similarCode` (необязательный запасной код)

### Попадание по каталогу

- `kind`: `exact` или `similar`
- `code`, `name`, `line`

Порядок:

1. В тексте есть `code` как отдельный токен — `exact`. Самый длинный такой код побеждает. Фрагмент материалов не кладётся.
2. Иначе есть `similarCode` как токен — `similar` («похоже»).
3. Иначе, если есть снимок CRM и в `spokenProducts` есть код или название строки, а живой текст к этой строке близок — эта строка, `similar`. История не даёт `exact`.
4. Иначе ближайшее `name` по пересечению букв — `similar`. Ничего близко — блок каталога пустой; «кто» и скрипт стадии остаются.

Шаг 3 локально не срабатывает (снимка нет). Правило нужно SaaS.

### Фрагмент материалов

- `text`, `source` (имя файла сейчас; id документа в хранилище позже)

Только с попаданием `similar`, под строкой каталога. Запрос — живой текст. Нет близкого куска — карточка без фрагмента, аналог остаётся.

### Подсказка словаря

- `heard`, `written`, `source`

Сами в словарь не пишутся. На карточке звонка их нет.

### Инструкция к живой подсказке

- `text` — пусто = только паразиты / шум, смысл не резать; непусто = только этот текст
- область — подсказка на карточке, не транскрипт

### Карточка на компьютере менеджера

Только после удачной привязки к этому `pcId`:

- из события и привязки: `callId`, `extension` / трубка, `managerName`, `callerNumber`, `direction`
- `client` — снимок или отсутствие
- `catalog` — попадание или отсутствие
- `rag` — фрагмент или отсутствие
- формулировка подсказки уважает инструкцию tenant (п. 4)

### Стенд локальной пробы (не продукт)

Те же поля, что позже заполнит телефония, но руками:

- `extension`, `callerNumber`, `managerName` — из полей панели
- `trunk` — пустой
- `direction` — `inbound`
- `callId` — местный, новый на каждое нажатие
- `source` — `stand-in`

Пустой добавочный или пустое имя менеджера — привязки нет, кнопка карточку не открывает. Номер может быть пустым.

## Индекс материалов (RAG)

Сейчас — папка `.txt` / `.md` на этом компьютере. Файлы никуда не отправляются. Позже — хранилище материалов организации. Меняется место, не роль.

Индекс не каталог и не CRM. Он не выбирает менеджера и не отвечает «кто звонит». Из него: один фрагмент на карточку и список подсказок словаря. Третьего потребителя нет.

## Расшифровка записи (файл звонка) — формы для SaaS

С 1.19.0 локальная расшифровка файла пишет то же, что потом может хранить сервис для записи звонка. Без привязки к Windows:

- **кусок** `TranscriptSegment`: `start`, `end` (секунды в исходной записи, реальные границы после нарезки по паузам, кусок ≤ 24 с), `text`
- **сырой текст** — куски по порядку, строка на кусок, по желанию `[hh:mm:ss]` начала куска; хранится всегда
- **субтитры** — SubRip из тех же кусков (`start --> end`)
- **обработка мозгом** — отдельный документ рядом с сырым: абзацы (несколько кусков подряд, метка первого куска), из которых убраны только слова-паразиты (длина ответа проверяется: 55–125 % исходной, иначе абзац остаётся как был), и раздел «Кратко» (пункты по частям, затем сведение). Куски отправляются порциями под контекст модели; размышления модели выключены. Облачный провайдер — только после явного согласия на отправку текста.

Сервису останется только сменить место: файл звонка из телефонии вместо пути на диске, хранилище вместо папки рядом с записью. Формат кусков и порядок шагов те же.

## Что остаётся за этим документом

Как хранить привязки, какой движок у поиска по материалам, транспорт доставки карточки на ПК и стек бэкенда — не здесь. Контракт — сценарий выше: **привязка ПК один раз → событие (webhook / softphone / клавиша) → совпадение с этим ПК → CRM (или пусто) → скрипт / каталог / один RAG → карточка; инструкция tenant только для подсказки.**
